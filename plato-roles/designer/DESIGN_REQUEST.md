## .dr.md Specification (DR Specification)

`.dr.md` (design review request) is the review request generated by the Designer agent at the end of the design phase, used to confirm the design summary and how external dependencies will be handled with the user.

### Format

```
Requirement: <summary of the requirement>
Design: <summary of the design>
External Dependency Status: <all satisfied, partially satisfied, or unsatisfied — who is being waited on and how long it will take>
External Dependency Strategy: <must all external dependencies be satisfied before starting, or should the design scope be adjusted to start with what's partially satisfied?>

**New Rules**
<rule file>: <rule text>
```

Example:

```
**New Rules**
rules/NEVER.md: Don't start without external dependencies
```

### Field Descriptions

- **Requirement**: Summary of this ticket's requirement, based on `REQUIREMENT.md` and the clarifying Q&A.
- **Design**: Summary of this design, i.e. a condensed version of the "Design" section in `DESIGN.md`.
- **External Dependency Status**: Describe the current satisfaction status of external dependencies — all satisfied / partially satisfied / not satisfied at all. For anything unsatisfied, state who needs to confirm it and the expected wait time.
- **External Dependency Strategy**: Describe how to handle unsatisfied external dependencies — either wait until all external dependencies are satisfied before starting implementation, or narrow/adjust the design scope to start with what is already satisfied.
- **New Rules**: Optional, one rule per line, format `<rule file>: <rule text>`. The user specifies which rule file the new rule should be added to (e.g. `rules/NEVER.md`). Leave empty if there are no new rules to add.

### On Approval

If `.dr.md` is approved and the **New Rules** section is not empty, for each `<rule file>: <rule text>` line, append `<rule text>` to `<rule file>`. If `<rule file>` does not exist yet, create it first.
