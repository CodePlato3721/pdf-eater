## Design

Persist the uploaded-file list to a new JSON file the same way chat history is already persisted, and restore it on startup the same way chat history is already restored, so the document list survives a service restart instead of coming back empty.

## Source Details

- `backend/config.py`: `UPLOADED_FILES_PATH = "data/uploaded_files.json"`
- `backend/utils/file_utils.py` (new): module-level `save_json(path, data)` / `load_json(path, default)` — the JSON read/write boilerplate `save_history()`/`load_history()` used to duplicate, now a reusable utils-layer function pair, sitting below `services/`. `save_json` normalizes `parent_dir = os.path.dirname(path) or "."` up front so `os.makedirs(parent_dir, exist_ok=True)` runs unconditionally, instead of branching on whether `parent_dir` is non-empty. `load_json` returns `default` if the file is missing or on read error.
- `backend/services/state.py::AppState`: `save_history()`/`load_history()` refactored to call `save_json`/`load_json` from `utils/file_utils.py`; added `save_uploaded_files()` (writes `loaded_files`, full replace) and `load_uploaded_files()` (reads `loaded_files`, defaults to `[]`), built the same way.
- `backend/services/ingestion.py`: `ingest()` calls `app_state.save_uploaded_files()` right after `app_state.loaded_files` is set; `restore()` calls `app_state.load_uploaded_files()` after the FAISS restore attempt, or clears `app_state.loaded_files = []` instead if that attempt's `except` branch ran.

## Test Details

Unit tests added covering: `save_json()`/`load_json()` round-trip and replace-not-append semantics, parent-dir creation, default-on-missing/corrupt-file behavior, and writing correctly when `path` has no directory component; `save_uploaded_files()`/`load_uploaded_files()` round-trip and replace-not-append semantics; `load_uploaded_files()` leaves `loaded_files` empty with no error and no file created when the file is absent; existing `save_history()`/`load_history()` behavior unchanged after the utils-layer extraction; `ingest()` writes `loaded_files` to `UPLOADED_FILES_PATH`, replacing prior contents; `restore()` populates `loaded_files` from disk when the FAISS index restores successfully; a fresh `restore()` with nothing ever uploaded leaves `loaded_files` empty; `restore()` clears `loaded_files` (ignoring stale JSON) when FAISS index restore raises; an `ingest()` → `restore()` round trip (simulated restart) leaves `loaded_files` matching the previously uploaded filenames.

## New Rules

COD.md: When a helper value can be empty/absent but a later unconditional step is always needed regardless (e.g. `os.makedirs`), resolve the value to a safe default at the point it's computed (e.g. `x = f() or default`) instead of branching later — keep the step that must always run unconditional rather than wrapped in `if value:`.
COD.md: **`backend/utils/`** holds framework-agnostic, dependency-free helper functions with no business/domain logic (e.g. generic JSON file I/O) that both `services/` and `core/` can share; it sits below both layers and must not import from either.
